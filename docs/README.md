## 📅 文档生命周期规则

### 新鲜度要求

| 文档类型 | 验证周期 | 过期信号 | 负责人 |
|----------|---------|----------|--------|
| ADR | 按 Revisit Triggers 触发 | 关联代码/配置已变更但 ADR 未更新 | 技术负责人 |
| 风险登记册 | 每月审查 | 最后更新 > 30 天 | 技术负责人 |
| 部署文档 | 每季度 + 每次部署变更 | 最后验证 > 90 天 | 运维负责人 |
| 安全加固文档 | 每季度 | 最后审查 > 90 天 | 安全负责人 |
| 法律协议 | 每半年 + 法规变更即时 | 无版本号或生效日期 | 产品/法务 |
| Code Wiki | 每半年 + 架构变更时 | 最后更新 > 180 天 | 技术负责人 |
| 质量审查报告 | 每次大版本后 | 落后 2 个以上版本 | 技术负责人 |

### 文档状态定义

| 状态 | 说明 |
|------|------|
| ✅ 活跃 | 最新有效，与系统现状一致 |
| ⚠️ 待更新 | 接近验证周期，需安排审查 |
| 🔴 已过期 | 超过验证周期，内容可能已不准确 |
| ⏳ 迁移中 | 过渡期间文档，迁移完成后归档 |
| 📦 已归档 | 历史文档，仅供参考，不代表当前状态 |

## 🛠️ Docs-as-Code 规范

### 文档变更流程

1. **修改**：在对应位置编辑 Markdown 文件
2. **更新元数据**：同步更新 `最后更新` 日期和 `版本` 号
3. **PR 审查**：关键文档变更需对应负责人 review
4. **合并**：合并后即为最新权威版本

### 格式要求

- 所有工程文档使用 Markdown 格式
- 文档头部必须包含：标题、版本、最后更新、责任方
- 使用相对路径交叉引用，确保可移植性
- 代码、配置、路径使用反引号标注
