# 核心不变量与锁定清单

> 本文档列举项目中必须保持稳定的核心环节、数据不变量和接口契约。后续优化/重构时，这些内容不得随意改动，否则会导致业务逻辑错乱或安全漏洞。

---

## 一、数据模型层（Database Invariants）

### 1.1 用户角色体系

| 不变量 | 说明 | 涉及表/字段 |
|--------|------|-------------|
| **唯一超级管理员** | 系统有且仅有 1 个 superadmin，邮箱固定为 `admin@manktv.com` | `User.role`, `User.email` |
| **角色层级严格有序** | `user`(1) < `admin`(2) < `superadmin`(3)，层级关系不可变 | `User.role` |
| **角色只能向下操作** | 只能看到/操作角色层级 **严格低于** 自己的用户 | - |
| **不能删除自己** | 任何管理员不能删除自己的账号 | - |
| **删除需二次确认** | 删除用户必须验证操作者密码 | - |

**锁定文件**：
- `server/src/middleware/auth.ts` — 角色层级校验逻辑
- `server/src/routes/admin.ts` — 用户管理操作（含事务回滚）
- `server/prisma/seed.ts` — 启动时唯一性纠偏

### 1.2 额度系统

| 不变量 | 说明 | 涉及表/字段 |
|--------|------|-------------|
| **余额恒等式** | `remainingTokens = totalTokens - usedTokens` 始终成立 | `UserQuota` |
| **原子预扣** | 额度扣减必须用 `updateMany + where gte` 原子操作，禁止先查后改 | `UserQuota.remainingTokens` |
| **失败必退还** | AI 生成失败时必须退还预扣的积分 | - |
| **充值原子增加** | 充值到账使用 `increment` 原子操作，禁止读改写 | `UserQuota.totalTokens`, `remainingTokens` |

**锁定文件**：
- `server/src/lib/generation.ts` — 额度扣减核心逻辑
- `server/src/middleware/generation.ts` — `withGeneration` 中间件
- `server/src/routes/billing.ts` — 充值事务

### 1.3 UID 账号体系

| 不变量 | 说明 | 涉及表/字段 |
|--------|------|-------------|
| **UID 全局唯一** | 每个用户的 uid 唯一且不可变 | `User.uid` |
| **UID 单调递增** | 新用户 UID 始终大于已有用户的最大 UID | - |
| **UID 不可修改** | UID 一经生成，任何接口不得修改 | - |
| **首次登录自动生成** | 用户首次登录（无论何种方式）自动分配 UID | - |

**锁定文件**：
- `server/src/lib/uidGenerator.ts` — UID 生成器
- `server/src/routes/auth.ts` — 注册接口
- `server/src/lib/emailCode.ts` — 邮箱验证码登录
- `server/src/lib/wechatLogin.ts` — 微信登录

### 1.4 内容审核

| 不变量 | 说明 | 涉及表/字段 |
|--------|------|-------------|
| **双审核必走** | 所有 AI 生成必须经过「输入审核 → 生成 → 输出审核」流程 | `ModerationLog` |
| **审核记录 Append-Only** | 审核记录只能创建和查询，**绝对不能有 update/delete 接口** | `ModerationLog` |
| **风险等级自动升降** | 用户 riskLevel 根据违规次数自动调整，规则不可随意改 | `User.riskLevel`, `violationCount` |
| **风险 3 级封禁生成** | riskLevel ≥ 3 时拒绝所有 AI 生成请求 | - |

**锁定文件**：
- `server/src/lib/moderation.ts` — 双审核核心
- `server/src/lib/llmRoute.ts` — LLM 路由封装
- `server/src/routes/adminModeration.ts` — 审核管理

### 1.5 社区功能

| 不变量 | 说明 | 涉及表/字段 |
|--------|------|-------------|
| **点赞联合唯一** | 同一用户对同一作品只能点赞一次（`workId + userId` 联合唯一） | `Like` 表 |
| **点赞计数一致性** | Like 表记录数 = Work.likesCount，操作必须在同一事务 | `Like`, `Work.likesCount` |
| **下架非物理删除** | 作品下架使用 `hidden` 字段，不做物理删除 | `Work.hidden` |
| **评论删除权限** | 仅评论作者本人 / admin / superadmin 可删除 | - |

**锁定文件**：
- `server/src/routes/community.ts` — 社区接口

### 1.6 配置系统

| 不变量 | 说明 | 涉及表/字段 |
|--------|------|-------------|
| **配置变更必有审计** | 所有 SiteConfig 修改必须写入 SiteConfigAuditLog，且在同一事务 | `SiteConfig`, `SiteConfigAuditLog` |
| **配置组+键唯一** | `group + key` 联合唯一，不可重复 | `SiteConfig` |

**锁定文件**：
- `server/src/lib/siteConfig.ts` — 配置读写 + 审计

## 二、认证与安全层

### 2.1 认证方式

| 不变量 | 说明 |
|--------|------|
| **JWT 密钥强度** | JWT_SECRET 长度 < 16 字符时服务直接退出，禁止弱密钥 |
| **Token 过期时间** | 默认 7 天，不可随意延长 |
| **密码哈希算法** | bcryptjs 10 轮，不可降低轮数 |
| **401 自动清理** | 前端收到 401 响应自动清除本地 token |

**锁定文件**：
- `server/src/lib/jwt.ts`
- `server/src/middleware/auth.ts`
- `web/src/services/api.ts`

### 2.2 登录方式契约

| 方式 | 请求字段 | 返回字段 | 说明 |
|------|----------|----------|------|
| 密码登录 | `account`, `password` | `token`, `user{id,uid,email,nickname,avatar,role}` | account 支持 UID 或邮箱 |
| 邮箱验证码 | 发送：`email` / 登录：`email`, `code` | `token`, `user` | 新用户自动注册 |
| 微信扫码 | 获取：`sceneId`, `qrCodeUrl` / 轮询：status | `token`, `user` | 新用户自动注册 |
| 注册 | `email`, `password`, `nickname?` | `token`, `user` | 新用户赠送积分 |

**锁定文件**：
- `server/src/routes/auth.ts`
- `web/src/store/useAuthStore.ts`

### 2.3 安全中间件

| 中间件 | 不可变行为 |
|--------|-----------|
| **CORS** | 生产环境强制 HTTPS + 白名单域名 |
| **Helmet** | HSTS / frameguard / xssFilter / noSniff 必须启用 |
| **限流** | 登录/生成接口必须有限流保护 |
| **请求体大小** | 10MB 上限，防止大请求攻击 |
| **API 不缓存** | 所有 /api/ 响应 `Cache-Control: no-store` |

**锁定文件**：
- `server/src/index.ts` — 全局中间件配置
- `server/src/middleware/rate-limit.ts`

## 三、业务流程层

### 3.1 AI 生成流程（核心）

```
用户请求 → 鉴权 → 风险等级检查 → 额度只读预检 →【原子预扣额度】
  → 输入审核 → 调用 AI 模型 → 输出审核 → 记录生成日志
  → 成功：累加 usedTokens / 失败：退还额度
```

**关键锁定点**：
1. **原子预扣必须在审核之前**（防止绕过额度检查）
2. **失败必须退还**（网络错误、审核拦截都算失败）
3. **生成日志必写**（无论成功失败，都要有记录）
4. **异步任务模式也要走相同的预扣逻辑**

**锁定文件**：
- `server/src/middleware/generation.ts`
- `server/src/lib/generation.ts`

### 3.2 LLM 接口通用流程

```
请求 → 风险门控 → 输入审核 → 主模型调用 → 输出审核 → 失败 fallback → 返回
```

**关键锁定点**：
1. 所有 LLM 接口必须走 `llmRouteJson` / `llmRouteText` 封装
2. 主模型失败时必须有 placeholder 兜底（不能直接报错）
3. 响应格式统一：`{ ok, source, placeholder, data }`

**锁定文件**：
- `server/src/lib/llmRoute.ts`

### 3.3 异步任务流程

```
创建任务 → 预扣额度 → 入队 → Worker 消费 → 执行 → 更新状态
  → SSE/轮询通知前端 → 成功/失败结算额度
```

**关键锁定点**：
1. 任务创建时必须预扣额度
2. Worker 失败也要结算（退还）
3. 任务状态只能前进，不能回退（pending → processing → completed/failed）

**锁定文件**：
- `server/src/lib/taskQueue.ts`
- `server/src/lib/taskWorker.ts`

## 五、接口契约（API Contract）

### 5.1 统一响应格式

| 类型 | 格式 |
|------|------|
| **成功** | `{ data }` 或直接返回数据 |
| **失败** | `{ error: "错误信息" }` + 对应 HTTP 状态码 |
| **分页** | `{ items, total, page, pageSize }` |

| 接口 | 方法 | 用途 |

| `/api/auth/register` | POST | 注册 |
| `/api/auth/me` | GET | 获取当前用户信息 |
| `/api/auth/email/send-code` | POST | 发送邮箱验证码 |
| `/api/auth/email/login` | POST | 验证码登录 |
| `/api/auth/wechat/qrcode` | GET | 获取微信二维码 |
| `/api/auth/wechat/status/:id` | GET | 轮询扫码状态 |
| `/api/quota` | GET | 获取用户额度 |

## 八、新增功能检查清单

新增功能时，必须确认以下事项：

1. **权限**：是否需要登录？需要什么角色？是否正确使用 auth 中间件？
2. **额度**：是否消耗积分？是否走 withGeneration 原子预扣？
3. **审核**：是否涉及用户输入/AI 输出？是否走双审核？
4. **日志**：是否有生成记录/审核记录？
5. **限流**：是否需要限流？是否接入 rate-limit？
6. **参数校验**：是否使用 Zod validate 中间件？
7. **错误处理**：是否有 try/catch？错误格式是否统一？
8. **前端**：AuthStore / QuotaStore 是否正确联动？
