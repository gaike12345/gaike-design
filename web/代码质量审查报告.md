## 二、Lint 与 TypeScript 配置审查

### 2.1 oxlint 配置（.oxlintrc.json）

**问题：规则覆盖严重不足**

当前配置仅启用 2 条规则：
```json
{
  "plugins": ["react", "typescript", "oxc"],
  "rules": {
    "react/rules-of-hooks": "error",
    "react/only-export-components": ["warn", { "allowConstantExport": true }]
  }
}
```

**缺失的关键规则建议补充：**

| 规则 | 类别 | 建议级别 | 理由 |
|------|------|---------|------|
| `no-unused-vars` | typescript | warn | 检测未使用变量 |
| `no-explicit-any` | typescript | warn | 限制 any 类型滥用 |
| `eqeqeq` | oxc | error | 强制使用 === 而非 == |
| `no-eval` | oxc | error | 禁止 eval |
| `no-implied-eval` | oxc | error | 禁止隐式 eval |
| `react-hooks/exhaustive-deps` | react | warn | useEffect 依赖完整性 |
| `no-console` | oxc | warn | 生产代码避免 console.log |
| `prefer-const` | oxc | warn | 优先使用 const |

### 2.2 TypeScript 配置（tsconfig.app.json）

**发现的问题：**

| 配置项 | 当前值 | 问题 | 建议 |
|--------|-------|------|------|
| `noUnusedLocals` | `false` | 未使用的局部变量不报错，易积累死代码 | 建议设为 `true` 或 `"all"` |
| `noUnusedParameters` | `false` | 未使用的函数参数不报错 | 建议设为 `true` |
| `strict` | 未设置 | 未启用严格模式（默认值为 false） | **强烈建议启用** `strict: true`，获得完整类型安全 |
| `noImplicitAny` | 未设置 | 隐式 any 不报错 | strict 模式下自动启用 |
| `strictNullChecks` | 未设置 | 空值检查不严格 | strict 模式下自动启用 |

> **重要风险**：未启用 `strict` 模式意味着 TypeScript 的大部分类型安全特性被关闭，`any` 类型可以隐式存在，这大幅降低了 TS 的价值。建议优先级最高。

## 六、架构与一致性问题

### 6.1 Store 目录模式不一致

`src/store/` 目录下共 16 个文件，但职责和命名模式混杂：

| 类别 | 文件 | 模式 |
|------|------|------|
| **标准 Zustand Store** | useAuthStore, useQuotaStore, useQuotaModalStore, useProjectStore, useModelStore, useNovelStore, useStudioStore, useUnifiedCanvasStore, useLayoutStore, useScriptGenStore, useWRToolsStore, useEditorStore, useFeatureStore | `create<State>((set, get) => ({...}))` |
| **组合 Hook（非 Store）** | useScriptStore | 内部组合多个子 store，用 `useShallowStore` 聚合状态。**命名为 useXxxStore 但实为自定义 Hook，易误导** |
| **工具函数（非 Store）** | useShallowStore | 通用 selector hook |
| **纯类型/常量模块** | canvasBase.ts | 无状态、无副作用，仅导出类型和工具函数。**放在 store 目录下不合理** |

**建议：**
1. 将 `canvasBase.ts` 移至 `src/lib/` 或 `src/types/` 目录
2. 将 `useShallowStore.ts` 移至 `src/hooks/` 目录
3. 考虑重命名 `useScriptStore` 为 `useWritingPane` 或 `useScriptPanel`，明确其为组合 Hook 而非独立 store

### 6.2 localStorage Key 管理分散

当前至少有 5 个不同的 localStorage key 散落在各处：

| Key | 位置 | 用途 |
|-----|------|------|
| `'mank_tv_token'` | services/api.ts | 认证 token |
| `'token'` | pages/AudioPage.tsx | 认证 token（与上不一致！） |
| `'mank_tv_dev_auth'` | components/AuthGuard.tsx | 开发绕过 |
| `'unified_canvas_state'`（推测） | store/useUnifiedCanvasStore.ts | 画布状态持久化 |
| `'imageModelSort'` | components/canvas/UnifiedNodes.tsx | 模型排序偏好 |
| `'videoModelSort'` | components/canvas/UnifiedNodes.tsx | 模型排序偏好 |

**建议**：集中管理 localStorage key（如在 `services/api.ts` 或新建 `constants/storage.ts` 中统一定义），避免硬编码字符串散落各处。

### 6.3 API 调用方式不统一

- 大部分请求通过 `api.get/post/put/del()` 封装（自动携带 token、处理 401/402）
- `AudioPage.tsx` 中有 3 处直接使用原生 `fetch` + 手动拼接 Authorization header
- `api.ts` 中 `uploadFile` 也有独立的 401/402 处理逻辑（与 `apiFetch` 重复）

**建议**：音频上传也应复用统一的 API 封装，或抽取公共错误处理逻辑。
